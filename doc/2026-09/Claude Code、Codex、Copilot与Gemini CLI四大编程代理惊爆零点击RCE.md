#  Claude Code、Codex、Copilot与Gemini CLI四大编程代理惊爆零点击RCE  
原创 网空闲话
                    网空闲话  网空闲话plus   2026-09-18 23:35  
  
据Air Security研究实验室9月17日的博文披露，一个名为  
**Plugin4Shell**  
的零点击远程代码执行漏洞，同时影响Claude Code、OpenAI Codex、GitHub Copilot和Gemini CLI。Air Security称其为首个AI代理生态供应链漏洞；其核心不是模型被越狱，也不是单一产品实现失误，而是四家厂商在插件安装与自动更新中重复了同一个设计错误：**代理按市场提供的SHA固定值检出代码，却从不验证工作目录中实际落地的提交是否就是被固定的提交**  
。结果是，经过审查、已被信任并固定的插件，可在用户毫无交互的情况下被替换为恶意版本，攻击者由此获得与使用者同等权限的远程代码执行能力。Air Security估计，潜在受影响代理规模达数百万。

### 一、漏洞成因与机制  
  
AI代理的插件和技能通常来自开放社区市场。企业安装插件后，代理会继承员工对敏感数据、内部系统和生产环境的访问权限。为防“先审查、后投毒”的供应链攻击，行业普遍采用**SHA pinning**  
：市场审查某一提交，将插件固定到该Git提交，理论上后续上游变化不应影响已批准版本。  
  
Plugin4Shell恰恰破坏这一保证。代理执行类似git clone  
后git checkout <pinned-sha>  
，但Git在名称同时是有效引用和对象ID时，会优先解析为引用，只打印“refname is ambiguous”警告。攻击者控制插件仓库后，可创建一个名称正好等于40位固定SHA的分支，并将其设为默认分支。于是git checkout  
检出的是恶意分支，而非固定提交；代理却报告“安装成功”。更危险的是，相同检出逻辑会在后台自动更新时再次运行。Claude Code和Codex默认自动更新已安装插件，因此市场一旦更新固定值，恶意替换就会无提示、无点击地进入已安装环境。  
  
Gemini CLI的机制略有不同：它使用git clone --depth 1  
、git fetch origin <pinned-sha>  
，再执行git checkout FETCH_HEAD  
。若仓库默认分支本身命名为FETCH_HEAD  
，检出会解析到该分支，正确获取的提交被静默丢弃，攻击者默认分支内容得以执行。有效修复必须在代理侧完成：检出后解析实际HEAD，并断言其等于固定SHA，否则中止安装：  
  
bash  
```
```  
  
  
关键是要检查解析后的HEAD，而不是请求的引用名。由于固定值在客户端解析，市场端无法独自修复该问题。

### 二、零点击攻击链  
  
Plugin4Shell有两条主要利用路径。其一，攻击者先向受信任市场发布真正良性的插件，通过审查并获得采用，随后将上游内容替换为恶意版本。其二，劫持合法作者的插件仓库，再利用Plugin4Shell绕过版本固定，将恶意版本推送给所有已安装代理。Air Security此前已在“The Story of Skills”中证明恶意技能可感染超过26,000个代理，在“SkillJacking”中证明925个技能被劫持、影响134,000个代理。前置投毒与仓库劫持已被证明可大规模发生，Plugin4Shell则补上了绕过防护机制的关键一步。

### 三、影响范围与潜在后果  
  
影响不限于粗心安装插件的用户。即使组织严格审查插件并将版本固定到已审提交，Plugin4Shell仍会令审查通过、固定写入，却安装不同代码。所有下游基于pinning的审核流程都会继承这一失败。攻击者获得的是员工级权限，可触及代理能访问的全部资产和数据；在CI环境中，还可能危及部署密钥、签名材料和注册表令牌。Air Security特别说明，使用Air Marketplace和Air Filter的企业未受Plugin4Shell影响。

### 五、关联案例：GitSpawn与SymJack  
  
Plugin4Shell并非孤立事件。GitSpawn显示，Claude Code、Qwen Code、Grok Build等代理在后台执行git status  
、git diff  
时，未清理项目.git/config  
中的core.fsmonitor  
等危险配置，恶意项目可令Git在索引更新时执行任意命令。该攻击需项目携带.git  
目录，例如ZIP、同步目录或外接存储。Manifold Security共发现7款代理中的8个问题；Goose获CVE-2026-72718，评分7.0；Hermes获CVE-2026-71963。Claude Code 2.1.196、Goose 1.44.0、Codex和Cursor已修复，但Qwen Code 0.22.3、Grok Build 1.0.13、Hermes 0.21.0及Claude Code ultrareview 2.1.252截至2026年9月1日仍未修复。  
  
SymJack则利用符号链接与确认窗口的认知差：用户以为在复制视频文件，实际写入的是MCP配置，重启后代理加载恶意服务器并执行命令，可导致SSH密钥、云令牌和会话数据泄露。Adversa AI的Рони Утевски测试了Claude Code、Gemini CLI、Antigravity CLI、Cursor Agent CLI、GitHub Copilot CLI、Grok Build和OpenAI Codex CLI。供应商反应不一：Anthropic曾拒绝报告但后来强化确认窗口；Google和Cursor未认定为新漏洞；OpenAI称Codex CLI场景为理论性；GitHub和xAI未回应。

### 六、评论与缓解建议  
  
Air Security强调，因为pin在代理内部解析，市场无法完全关闭该漏洞，只有代理侧修复才能恢复保证；市场端只能通过只允许拒绝SHA形分支名的托管商来削弱分支名变体，实际等于GitHub-only，但这会排除代理官方支持的托管商，且对Gemini CLI变体无效。SecurityLab也指出，仅控制扩展目录不够，可靠修复必须比较实际HEAD与固定SHA。Manifold Security建议检查.git/config  
，开发者应禁用后台Git调用中的危险参数。Adversa AI认为确认模型本身是弱点，建议检查符号链接、禁止代理通过shell写入配置目录、关闭项目MCP自动启动，并隔离处理不可信合并请求的CI环境。  
  
综合来看，Plugin4Shell与GitSpawn、SymJack共同说明：AI代理的安全边界已从模型扩展到插件市场、Git解析、项目配置和确认界面。只审查市场不够，只固定SHA也不够；代理必须在本地验证实际执行的代码，行业也需要把插件权限、自动更新和Git行为纳入纵深防御。
