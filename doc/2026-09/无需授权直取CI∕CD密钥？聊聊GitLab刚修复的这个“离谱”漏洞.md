今天本来想安安静静敲会代码摸个鱼，结果一刷安全圈的新闻，好家伙，**GitLab 又双叒叕爆大雷了！**  
  
这次官方直接给出了一个   
CVSS 评分 10.0 的“满分”漏洞（CVE-2026-85706）  
。最刺激的是，这个漏洞在公开后的短短几个小时内，就已经被黑客在全网疯狂进行在野扫描和利用了。  
  
咱们来扒一扒这个漏洞的底层逻辑，看看它到底是怎么回事，利用路径是什么，以及咱们该怎么防。  
## 🚨 漏洞主角：CVE-2026-85706 到底离谱在哪？  
  
简单来说，这是一个位于 **Repository Commits API**  
（仓库提交API）中的 **路径遍历漏洞**  
。  
  
导致这个漏洞的根本原因，用 GitLab 官方的话来说就是：**“对API路径的限制不严，且缺少身份验证强制措施”**  
。  
  
这也就意味着，攻击者**完全不需要账号密码（未授权状态）**  
，只要向存在漏洞的 GitLab 服务器发送精心构造的请求，就能实现  
任意文件读取  
。  
> **🎯 漏洞触发的唯一门槛：**  
> 威胁情报公司 watchTowr 的安全专家 Jake Knott 透露，这个漏洞的利用条件低得令人发指——**目标 GitLab 实例上只需要存在至少一个“公开项目”即可**  
。  
  
### 🛠️ 技术攻击路径拆解  
  
虽然目前全网都在捂着 PoC，但从官方的安全通告和修复特征中，我们已经能清晰地描绘出它的攻击画像：  
  
攻击者主要通过向 GitLab 接口发送 **HTTP POST 请求**  
 来触发。重点关注的 URI 路径是：  
/api/v4/projects/{id}/repository/commits/  
  
在这个请求中，攻击者会利用 file.Path  
 参数进行路径穿越（比如经典的 ../../../../  
 骚操作），从而跳出沙箱限制，直接读取宿主机上的敏感文件。  
  
**一旦攻击得手，后果是毁灭性的：**  
- **窃取配置与日志：**  
 黑客可以读取 GitLab 的核心配置文件和系统日志，直接获取数据库密码、实例 Secrets。  
  
- **拿捏 CI/CD 命脉：**  
 未授权访问能让攻击者直接接触到源代码、CI/CD 密钥和各种凭证。  
  
- **供应链投毒：**  
 这是今年黑客最喜欢的剧本——通过注入代码到构建流水线，直接污染下游的所有产物。你的代码还没上线，就已经变成黑客的后门了。  
  
## 🎁 买一送一：还有一个 9.9 分的“隐藏雷”  
  
你以为这就完了？在这次更新中，GitLab 还顺手修了另一个极为凶险的漏洞 —— **CVE-2026-87719（CVSS 9.9分）**  
。  
  
这是一个存在于 **GitLab EE（企业版）**  
 中的 **不安全反序列化漏洞**  
。  
  
**技术实现难点与突破：**  
  
这个洞的门槛稍微高一点，需要攻击者拥有认证账号并且具有 **Duo Chat**  
 的访问权限。但它的利用手法非常巧妙：攻击者通过构造一个特殊的 **GraphQL 订阅参数**  
，成功绕过了系统的序列化防御机制，进而执行服务器对象查找。这最终会导致敏感的实例配置和凭证被无情泄露。  
## 🛡️ 排查指南：与时间赛跑  
  
目前，美国网络安全和基础设施安全局已经确认了 CVE-2026-85706 的在野利用，并在 9月11日 直接将其加入了 **KEV（已知被利用漏洞）目录**  
，要求联邦机构限期修复。  
  
各位运维和安全的兄弟们，这波从“漏洞披露”到“无差别大规模自动化攻击”的窗口期已经非常短了！  
立刻马上排查你的系统！  
### 1. 受影响版本列表  
  
无论你是社区版 (CE) 还是企业版 (EE)，请对照以下版本：  
- 18.7<= 版本 < 19.1.8  
- 19.2 <= 版本 < 19.2.6  
- 19.3 <= 版本 < 19.3.2  
### 2. 修复方案  
- **打补丁：**  
 赶紧升级到安全版本 **19.3.2、19.2.6 或 19.1.8**  
。  
  
- **缓解措施：**  
 如果你的 GitLab 实例不需要暴露在公网上，**立刻切断公网访问**  
，或者通过防火墙/WAF严格限制公网 IP 白名单。  
  
### 3. 应急溯源  
  
如果你怀疑自己已经被盯上了，赶紧去翻一下 Web 服务器和 GitLab 的访问日志。  
  
**重点排查特征：**  
  
查找包含 /api/v4/projects/{id}/repository/commits/  
 路径的 **HTTP POST 请求**  
，并仔细审查其携带的 file.Path  
 参数是否存在异常的路径穿越符（如 ../  
 等特征）。
