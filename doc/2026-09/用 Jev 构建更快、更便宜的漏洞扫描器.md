## 引言  
  
扫描代码漏洞正在成为软件开发生命周期（SDLC）中不可或缺的一环。然而，这件事对**人和 token 来说都很昂贵**  
。结果是组织要么扫描频率远低于应有水平，要么让代码库的大部分区域处于未检查状态。  
  
我们用 **Jev**  
做实验，构建了一个有效的漏洞扫描器，其表现**接近 GPT-5.6 Luna，而成本更低**  
。  
  
我们认为这条研究路线很重要，因为**黑客攻击正在变成一场效率游戏**  
。攻击者可以把全部精力投入到寻找**一个**  
高回报漏洞上；而防御者必须**持续覆盖每一个仓库、每一次提交**  
。在一个自主攻击已成常态的世界里，我们相信应当支持防御者重新思考他们的安全策略 [1][2][3]。  
  
在 depthfirst，我们痴迷于**高性价比的漏洞发现研究**  
，因为我们为之构建的世界是：当自主攻击变得普遍时，防御者能够持续、主动地保护自己的代码。  
## 我们是如何做到的  
  
过去几周，一种名为 **Jev**  
的新架构受到大量关注。**Jev 是一个分类器。**  
给它一些上下文、一个问题，以及一个选项列表，它会为每个选项输出一个概率。与 LLM 不同，它输出的是**概率**  
，而不是通过生成 token 序列来回答问题。  
  
你可以这样问 Jev：「这段代码有漏洞吗？」提供相关上下文，然后收到它对「真」的概率。  
  
![](https://mmbiz.qpic.cn/sz_mmbiz_png/h4gtbB74nSj5GmD62QFicKvekL2PB52XicPLHNuOG05ibvj3DCCDauoLm8ZrgG5ibibRpSF9qTrVjXLhQc3541mFoicw3L6KaBc6qtlKKzvw4rpNg/640?wx_fmt=png&from=appmsg "")  
  
对**通用缺陷枚举（CWE）**  
这类漏洞类型做分类也是同样的道理。我们可以针对每一个 CWE 向 Jev 提一个「真/假」问题。由于每个问题相互独立，我们可以**全部并行提问并缓存共享上下文**  
。  
  
![](https://mmbiz.qpic.cn/sz_mmbiz_png/h4gtbB74nSh9BExzj38JicWhkmO1PkoYPouJloZqkvmBYZnYBnoA8qO5SZhPZ7jKXia2ttmqqKsE9ke6jXCqwhl79bSEH42S7Nhqibhka4tjVw/640?wx_fmt=png&from=appmsg "")  
  
这既省时间又省钱。**输入价格为每百万 token 0.042 美元，比 Luna 便宜五倍，且输出免费。**  
每次调用耗时约**四分之一秒**  
，而 Luna 约为 **10 秒**  
。代价是它的**上下文窗口只有 32,000 token**  
，而 Luna 是 100 万 token。  
  
作为研究的一部分，我们围绕 Jev 构建了一个漏洞扫描器，看看它在 **dfbench**  
上的表现。这是一个新的运行框架，通过把整个扫描拆解成**分类任务**  
来绕开 32k 的上下文限制：  
- **找出可能含漏洞的代码。**  
首先把仓库切成小块。然后把每个块展示给 Jev，问它哪些块是安全关键的、或者根据任务最可能含有漏洞。概率最高的块成为后续步骤的**上下文**  
。  
  
- **判断是否存在漏洞。**  
Jev 带着第一步得出的上下文**并行**  
扫描每个块，定位潜在的漏洞。  
  
- **对漏洞及其细节进行分类。**  
随后向 Jev 提出一系列问题，以获取漏洞类型、攻击模式分类、不可信输入的**传播路径**  
（代码位置），然后定位攻击者可控输入**从哪里进入代码**  
、**在哪里造成危害**  
、**使其得以成立的缺陷检查或逻辑**  
，以及**可能的安全影响**  
。  
  
最终产出的是一个漏洞、它的位置，以及攻击者可以如何利用它。  
  
由于该扫描器**可并行化**  
且每次调用都很快，完整扫描用 Jev 只需**约 2 秒**  
，而大多数其他模型**至少需要 3 分钟**  
。

## 局限  
- **我们的 Jev 扫描器只会回答我们想到要问的问题。**  
我们必须在运行框架中纳入相关的漏洞发现问句，然后由 Jev 来回答。不过，把 Jev 与 LLM 智能体耦合起来可能带来更好的表现，因为智能体能注意到我们构建运行框架时未曾预料到的东西。  
  
- **我们的 Jev 扫描器够深入，但仍可进一步扩展。**  
Jev 在覆盖整个代码库扫描漏洞方面**非常高效**  
。然而，许多真正被利用的漏洞需要**连接不同部分**  
，这需要更强的推理能力——LLM 在这方面强得多。Jev 仍可通过为 LLM 提供相关上下文来辅助这一过程。  
  
- **发现可能缺少足够上下文。**  
Jev 能对漏洞类型与攻击模式分类，但安全团队可能想要关于实际漏洞是什么、以及如何被利用的更多细节。可以用 LLM 来**丰富**  
Jev 的输出以提供这些信息。  
  
## 后续工作  
  
我们的 Jev 扫描器展现出很大潜力，可作为漏洞发现与验证的**极其廉价的第一遍筛选**  
。因为它**极快、每次扫描只需几美分**  
，可以用在以前因过于昂贵或不方便而无法覆盖的地方。  
  
例如，你可以用它扫描大型依赖树中的**每一个包**  
，或者给防御者提供一种**廉价的初筛手段**  
，在升级到更昂贵的模型之前先行分流。  
  
我们很期待继续构建更便宜、更强大的漏洞扫描器，让防御者无论攻击者移动多快，都能保持领先。
