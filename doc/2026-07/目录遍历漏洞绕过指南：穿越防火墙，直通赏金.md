路径穿越漏洞的挖掘过程，就像在和一台死板的文件管理员斗智斗勇。它会检查你的请求，但你总能找到它打瞌睡的时候。以下就是你绕开那些常见障碍的实战路数。  
  
第一招：用“套娃”序列迷惑过滤器  
  
有些防护很粗糙，只做一次简单的  
危险字符清除。你可以试试用  
嵌套的遍历序列，比如  
 ....// 或  
 ....\/。当系统傻傻地把内部的   
../ 剥离后，剩下的部分又会重新拼凑成一个有效的穿越路径。  
  
例如，拿   
Burp Suite 拦个获取图片的请求，把   
filename 参数改成：  
  
....//....//....//  
etc/passwd  
  
发出后瞅一眼响应，那个装着服务器账户信息的 passwd 文件，可能就直接摊在你眼前了。

第二招：给路径换个“马甲”  
  
在  
 URL 路径或者上传表单的  
 filename 参数里，服务器可能会先一步对你的输入做解码清理。这时，  
编码就是你的好朋友。把   
../ 这些字符做一次   
URL 编码（变成   
%2e%2e%2f），甚至做  
双重编码（变成   
%252e%252e%252f），往往就能溜过检查。还有些  
非主流编码，比如   
..%c0%af 或   
..%ef%bc%8f，有时也能出奇效。  
  
例如，在   
Burp 里，把   
filename 参数改成双重编码后的样子试试：  
  
..%252f..%252f..%252fetc/passwd  
  
发送请求，那个熟悉的 passwd 文件内容，就又回来了。  
Burp Suite Pro 的用户，可以直接用   
Intruder 里的  
 Fuzzing - path traversal 字典，里面塞满了这类编码好的弹药，非常方便。  
  
第三招：从合法路径“越狱”  
  
如果对方强制要求文件路径必须从一个指定的基础文件夹开始，比如   
/var/www/images，别慌。咱们可以假装顺从，先写上它要求的合法路径，然后立刻在后面接上  
回溯序列，直接从内部跳到系统根目录去。  
  
直接把 filename 参数构造为：  
  
/var/www/images/  
../../../etc/passwd  
  
这样前半段满足了规则检测，而后半段的跳转指令一执行，你就又能读取到敏感文件了。  
  
第四招：用空字节“截断”尾巴  
  
有时程序会强制检查  
文件名后缀，比如必须以  
 .png 结尾。  
空字节（%00）这种底层字符串终结符，在部分老旧的系统或代码里，能骗过后缀检查，让文件名在真正读取时被  
截断。  
  
例如，你可以这么构造请求，把 filename 参数改成：  
  
../../../etc/passwd  
%00.png  
  
系统在检查时看到的是   
.png 结尾，觉得一切正常；但在底层读取文件时，遇到  
 %00 就直接截断了，忽略掉假的扩展名，把   
passwd 文件内容原封不动地吐出来。
