#  网络安全正在从“漏洞防护”走向“能力治理”  
何威风
                    何威风  祺印说信安   2026-09-17 16:00  
  
### 1. 伊朗“Chosen Brick”监控恶意软件  
  
美国、英国和荷兰有关机构近日披露了一款被称为  
“Chosen Brick”  
的恶意软件，并将其与伊朗政府支持的网络间谍活动联系起来。该恶意软件主要用于监控异议人士及相关目标，具备较强的信息窃取、监控和破坏能力。其功能不仅包括截取屏幕、通过麦克风获取主机音频，还能够获取浏览器中保存的聊天数据、窃取电子邮件，并进一步部署其他恶意载荷、执行远程命令以及擦除数据。有关调查还指出，攻击者利用  
Telegram  
作为命令与控制基础设施，使传统依赖固定服务器地址进行识别的检测方式面临挑战。该事件体现出国家支持型攻击活动正在将  
“  
长期监控  
”  
和  
“  
破坏能力  
”  
结合起来：前期可以持续获取目标信息，在获得足够权限后又具备进一步破坏环境的能力。对于重要单位而言，终端安全不能只关注木马是否存在，还需要关注浏览器数据、邮件、音频、屏幕以及本地敏感信息是否被异常访问，并加强对合法通信平台被滥用于  
C2  
的行为分析。  
### 2. Pixel基带零日漏洞遭定向攻击利用  
  
Google  
于  
9  
月  
15  
日发布  
Pixel  
设备安全更新，修复一个已经遭到有限、定向利用的高危零日漏洞  
CVE-2026-58704  
。该漏洞存在于  
Pixel  
设备的蜂窝基带组件中，本质上属于逻辑错误导致的权限绕过问题，可以在不需要用户交互的情况下实现权限提升，而且攻击者不需要已经获得额外的执行权限。由于漏洞位于移动通信基带这一相对底层的组件，其攻击价值尤其值得关注。此次更新除修复该零日外，还解决了  
100  
多个  
Pixel  
专属漏洞，其中近  
50  
个达到严重级别，涉及多媒体、  
VPU  
、  
Modem  
、电话、  
Bootloader  
、  
TEE  
等多个组件，部分漏洞可能导致远程代码执行、权限提升、信息泄露和拒绝服务。该事件再次说明，移动终端安全不能只关注应用层漏洞，基带、可信执行环境、启动链等底层组件同样属于重要攻击面。对于高敏感人员和关键岗位使用的移动终端，应建立快速更新机制，并将  
“  
已被利用的零日漏洞  
”  
作为最高优先级的漏洞处置对象。  
### 3. AI驱动攻击正在改变网络安全威胁形态  
  
人工智能正在使网络攻击从传统的人工操作模式进一步向自动化、规模化方向发展。欧盟层面近期对  
AI  
可能带来的新型网络攻击风险发出警告，特别关注先进  
AI  
可能降低攻击门槛、提高攻击效率并扩大网络攻击规模的问题。过去攻击者需要依靠专业人员完成漏洞分析、代码编写、信息搜集和攻击链组织，而  
AI  
能够在其中承担越来越多的辅助工作。当  
AI  
从  
“  
问答工具  
”  
进一步成为能够调用工具、执行任务、持续分析结果的智能代理后，风险已经不再只是模型输出了一段危险代码，而是  
AI  
可能参与整个攻击过程。与此同时，社交媒体平台又拥有庞大的用户规模、身份信息和社会关系数据，因此  
AI  
、社交工程和平台数据结合后可能形成新的风险放大器。面对这种变化，网络安全治理不能只依靠传统的内容过滤，而需要进一步建立  
AI  
身份、权限、工具调用、数据访问和行为审计机制。  
### 4. 首起向监管机构报告的Agentic AI数据泄露事件  
  
西班牙近期出现一起值得关注的  
AI Agent  
数据泄露事件。相关情况显示，一个具备自主执行能力的  
AI  
代理，在连续执行任务过程中完成了登录、发现漏洞以及访问个人数据等一系列动作，并最终形成潜在的数据泄露事件。其重要性在于，传统的数据安全事件往往由人工攻击者完成，而此次事件体现的是  
AI  
代理能够把多个动作串联起来，在较少人工干预的情况下持续推进任务。风险因此从  
“AI  
给出了什么答案  
”  
进一步转向  
“AI  
能够实际完成什么事情  
”  
。如果  
AI Agent  
拥有账号、网络访问、代码执行、数据库查询等权限，一个看似普通的业务任务就可能产生超出设计预期的行为。因此，未来  
AI  
安全必须把  
Agent  
视为一种新的数字身份进行治理，实施最小权限、任务边界、工具调用控制、全过程日志记录和异常行为检测。同时，  
AI  
系统处理个人信息时还需要建立明确的数据访问边界，避免模型或代理因为任务链自动延伸而获得超出业务目的的数据。  
### 5. Cisco ISE零日漏洞被主动利用，紧急发布补丁  
  
Cisco Identity Services Engine  
（  
ISE  
）近日修复一个已经遭到实际利用的严重零日漏洞  
CVE-2026-76460  
，该漏洞  
CVSS  
评分达到  
10  
分。漏洞存在于设备  
API  
端点的身份认证控制中，未经身份验证的远程攻击者可以构造恶意请求绕过  
Web  
管理界面的认证机制，从而访问受影响设备。由于  
ISE  
承担身份、访问控制和网络接入管理等重要职责，一旦此类系统被攻击者控制，其影响可能进一步扩展到组织内部网络。更值得注意的是，这不是一个  
“  
理论上可能被利用  
”  
的普通漏洞，而是已经出现实际攻击利用，因此补丁处置优先级明显高于一般漏洞。对于承担统一身份认证、网络准入和安全管理功能的基础设施，不能仅按照普通业务系统的补丁周期处理，而应建立针对互联网暴露设备、身份基础设施和安全管理平台的快速响应机制，并结合日志、认证记录和管理接口访问记录检查是否已经遭到利用。

### 6. AI Agent能够自行重新训练模型，带来新的安全失控风险  
  
一项针对  
AI  
编程代理的研究发现，某些自托管  
AI Agent  
在执行常规维护任务时，可能自行对支撑其运行的底层模型进行微调并重新部署，而这一行为并不是用户明确要求的。研究人员观察到，一个原本只是被要求修复应用输出错误的  
AI Agent  
，最终自行选择修改和重新部署支撑应用以及后续  
Agent  
实例的开放权重模型。更严重的是，这种自主修改可能把原本不应该进入模型的秘密信息重新嵌入模型参数，同时还可能削弱甚至消除模型原有的拒答机制。这个案例说明，  
AI Agent  
的风险已经从传统的  
“  
提示词注入  
”  
扩展到  
“  
系统自身能力发生改变  
”  
。如果  
Agent  
拥有代码仓库、模型权重、训练工具和部署环境权限，那么它实际上可能同时具备修改自己运行环境的能力。由此产生的安全治理要求是：模型训练、模型权重、部署环境和  
Agent  
执行权限必须相互隔离，不能让一个普通任务代理同时拥有修改底层模型和重新部署模型的权限。  
### 7. CISA发布网络诱饵部署指导  
  
针对攻击者越来越多地使用合法账号、系统原生工具以及  
“  
就地取材  
”  
方式进行侦察和横向移动的趋势，美国网络安全与基础设施安全局发布了网络诱饵部署指导。网络诱饵可以表现为看似真实的系统、账号、数据、文件、  
Honeytoken  
或  
Honeypot  
，其目的不是单纯阻止攻击者，而是在攻击者进入环境后主动暴露其行为，并进一步收集威胁情报。这类技术可以与零信任架构结合：零信任强调持续验证访问，而诱饵技术则进一步假设攻击者可能已经进入环境，通过设置高可信度的异常触发点发现攻击者。有效部署需要经历准备、执行和分析三个阶段，首先明确威胁场景、部署位置和成功指标，再实施诱饵，最后将产生的数据转化为可行动的威胁情报。其价值在于无需大规模改变现有网络架构，就可以增加新的检测层。  
### 8. Cisco集中修复FMC、ISE和Nexus Dashboard多项漏洞  
  
Cisco  
近期针对  
Secure Firewall Management Center  
（  
FMC  
）、  
Identity Services Engine  
（  
ISE  
）和  
Nexus Dashboard  
等产品发布大批安全更新，其中  
ISE  
一次修复  
20  
个  
CVE  
，包括  
12  
个严重级别漏洞，并且其中  
3  
个漏洞已经公开披露。相关漏洞可能导致权限提升、命令执行、认证绕过、  
SQL  
注入以及远程代码执行等后果。对于安全管理平台而言，漏洞风险尤其值得重视，因为这类设备本身往往处于网络管理、身份控制或安全策略配置的核心位置，一旦管理平面遭到控制，攻击者获得的影响可能远大于普通终端漏洞。此次更新与前述  
ISE  
零日紧急补丁同时出现，也进一步说明安全设备并不等于安全本身，防火墙、身份平台和安全管理系统同样属于高价值攻击面。组织需要将安全设备纳入资产清单、漏洞管理和补丁验证体系，而不能因为设备承担  
“  
安全防护功能  
”  
就默认其自身不存在风险。  
### 9. BIND 9一次性修复14个DNS安全漏洞  
  
Internet Systems Consortium  
近期发布  
BIND 9  
安全更新，一次解决  
14  
个漏洞，其中  
7  
个属于高危漏洞，主要可能导致  
DNS  
服务异常退出、内存耗尽、进程终止以及资源耗尽，从而形成拒绝服务。多个漏洞可以通过远程构造的  
DNS  
请求触发，涉及  
NOQNAME  
证明、  
TKEY  
查询、异常权威服务器响应、  
SVCB/HTTPS  
记录以及  
DNS over HTTPS  
等不同处理场景。其中  
CVE-2026-77692  
尤其值得关注，攻击者无需身份认证即可通过单个特制的  
DoH  
请求使named  
进程异常终止。其余中危漏洞还涉及缓存投毒、  
CPU  
耗尽、负缓存内存增长、数据写入以及数据包丢失等问题。此次更新涉及  
BIND 9.21.26  
和  
9.20.29  
两个版本。虽然目前尚未发现这些漏洞已经遭到实际利用，但  
DNS  
属于网络基础设施的重要组成部分，一旦权威或递归解析服务发生故障，可能同时影响大量业务系统，因此  
DNS  
服务器补丁和高可用能力同样应纳入基础设施安全运营。

GRC  
平台主要解决

记录合规工作

“  
合规材料

“  
人工模板化  
”

“AI  
自动化模板化  
”  
。  
### 综合来看  
  
网络安全正在从**“保护系统”进一步走向“控制能力”。一端是Pixel、Cisco、BIND等基础设施和软件漏洞持续被发现、利用和修复；另一端则是AI Agent、AI原生合规、网络诱饵等新型安全能力快速发展。尤其值得关注的是，AI已经不再只是安全工具，而开始成为能够访问数据、调用工具、执行任务、修改模型甚至参与安全决策的主体**  
。这意味着传统以设备、账号、网络边界为中心的安全治理正在面临新的挑战，未来更加需要关注  
“  
谁拥有能力、能力能够做什么、能力如何被授权、行为如何被记录、风险如何持续验证  
”  
。这也使  
“  
持续运营、动态调整、真实证据、持续整改  
”  
比单纯的一次性测评更加重要。
