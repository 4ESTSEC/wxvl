#  OpenSSH 存在多处漏洞，可导致明文恢复、文件写入与注入攻击  
 网安百色   2026-10-07 10:19  
  
![](https://mmbiz.qpic.cn/sz_mmbiz_png/WibvcdjxgJnuu25pwq1G9A7KOOwAe6TBM3GuBRBGXhCwZicE1SpEROcH8Sp83ib0bhw66ia09X6qhibmKiaKGKaicG4E837FFBJicDuFicQFFGR8FHqY/640?wx_fmt=png&from=appmsg "")  
  
OpenSSH 10.6 于 2026 年 10 月 6 日发布，修复了一批安全缺陷。这些问题在特定条件下可能导致机密信息泄露、文件被写入预期目录之外，或引发 Shell 注入。本次更新同时覆盖客户端与服务端工具，因此所有依赖 SSH 进行远程访问和文件传输的管理员与用户均需关注。  
  
官方发布说明指出，这是多个攻击前提各不相同的独立弱点，并非单一漏洞通杀所有安装环境。核心问题集中在三处：SSH 通道间共享压缩字典、SFTP 服务端返回的路径，以及传入 Shell 命令的不可信用户名。  
  
**SSH 明文恢复风险：跨通道压缩侧信道**  
  
研究人员 Fabian Bäumer 与 Marcus Brinkmann 在论文《Crossing the Streams》中描述了这一压缩缺陷。当压缩功能开启时，同一 SSH 连接内的多个通道会共享一个压缩字典。攻击者若能向其中一个通道放入自选文本，并观测加密流量的长度变化，即可借此恢复另一通道中承载的机密信息。  
  
泄露根源在于 LZ77 压缩算法——它会将重复出现的文本替换为对先前数据的引用。一旦攻击者可控的文本与某段机密内容重合，生成的流量长度就会暴露线索。这并未直接破解 SSH 加密，而是利用了加密发生前由压缩环节泄露的信息。  
  
在研究人员噪声最低的一组测试中，从 26 个字母组成的字符集中抽取的 8 字符秘密值，最多只需 276 次猜测即可被恢复。该结果依赖于特定测试条件，不应被理解为通用的恢复效率。  
  
OpenSSH 10.6 在 ssh 与 sshd 两端均禁用了 LZ77 字典编码器。压缩功能仍然可用，但效果会打折扣。开发者建议在可行的情况下采用应用层压缩，避免让可信流量与不可信流量共用同一套 SSH 压缩上下文。  
  
**文件写入与注入类缺陷**  
  
SFTP 修复加强了对服务端返回路径的检查。在此之前，恶意服务端可提供特定路径，诱导递归拷贝操作将文件写入目标目录之外。研究员 Junghoon Cho 报告了该问题并提供了补丁。风险在于客户端如何处理服务端响应，而非未认证攻击者能向任意 SSH 服务器写入文件。  
  
另一项修复拦截了 SSH 命令行中提供的目标用户名里的美元符号（$  
）与反斜杠（\  
）。在某些配置下，来自不可信来源的用户名会经由 ProxyCommand  
、Match exec  
 或相关功能进入 Shell 上下文，从而引发注入。该问题由 SecBuddyF（腾讯科恩实验室，KeenLab Tencent）报告。通过配置文件中 User  
 指令设置的用户名不受此新限制约束。OpenSSH 提醒，字符过滤无法完全覆盖每一种 Shell 与环境组合，因此应用程序不应将不可信输入直接传入 SSH 命令行。  
  
**其他修正与平台限制**  
  
此版本还修正了 GSSAPI 凭据处理、隧道限制、过大的解压后数据包，以及证书日期转换等问题。在部分较老平台（包括 QNX 6 与 SCO OpenServer 5）上，它关闭了与保留 root 权限相关联的转发选项。  
  
部署更新时，管理员应复核这些变更，尤其是必须启用压缩或转发的场景。与此同时，维护方计划随着 AI 辅助报告的增多而提高发布频率，并警告称攻击者可能独立发现同类缺陷。对于这类报告，人工复核、测试用例以及补丁提案依然是验证工作的重要环节。
